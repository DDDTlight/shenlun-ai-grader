# 申论 AI 批改

一个跑在自己电脑上的申论批改小工具。**把答卷和参考答案一起丢进去，它逐条告诉你哪些要点答到了、哪些漏了、依据在材料的哪一段。**

给备考的人用。

```
贴资料（题干 + 材料 + 机构参考答案）  ┐
贴答卷                              ├─→  逐点命中情况 + 得分 + 材料依据
点「开始批改」                       ┘
```

## 支持什么

| 题型 | 状态 |
|---|---|
| 概括归纳题 | ✅ |
| 综合分析题 | ✅ |
| 提出对策题 | ✅ |
| 贯彻执行题（公文） | ✅ 再分 4 个子类：总结 / 宣传 / 方案 / 评论 |
| **文章写作（大作文）** | ❌ **明确不做** |

**为什么不做大作文**：议论文写法多样，同一道题有好几种都成立的结构和角度，无法逐条核「这个要点答到没有」。评分靠整体印象，而档位标准本身存在未裁决的冲突（判档制 vs 多维度加总；满分 30/35 两说并存；字数不足降档有四种互斥阈值）。

**标准没定就动手，只会做出一个需要推翻重来的版本。** 代码里用 `EXCLUDED_TYPES` 和「待做」区分开，遇到文章写作会直接报错，而不是拿小题的规则凑合批 —— 那只会得出一个没有意义的数字。

## 快速开始

### 方式一：下载便携版（推荐）

去 [Releases](../../releases) 下载 `shenlun-*-win-x64-portable.zip`。

```
① 解压（要整个解压，别在压缩包里直接双击）
② 双击 启动.bat
③ 浏览器自动打开 → 右上角「设置」填 DeepSeek API Key
```

**不需要装 Python。** 便携包里自带解释器和全部依赖。

### 方式二：从源码跑

```bash
pip install -r requirements.txt
python -m server.main
```

浏览器会自动打开 `http://127.0.0.1:8000`。

## 需要什么

- **Windows 10+**（Linux / macOS 从源码跑也行）
- **能上网** —— 批改时题目和答卷会发到 DeepSeek 的服务器
- **一个 DeepSeek API Key** —— 在页面右上角「设置」里填

Key 存在 `C:\Users\<用户名>\.shenlun\.env`（Linux/macOS 是 `~/.shenlun/.env`），**不上传到任何地方**，只用于调用 DeepSeek 官方接口。

## 它是怎么打分的

```
① 采点    从「机构参考答案」里提炼出给分单位（要点）
② 判点    逐条判断答卷有没有答到，且必须抄出答卷原句当证据
③ 规则    纯代码检查：字数、分条、公文格式
④ 计分    纯代码计算
⑤ 参照    再跑一条自由推理路径，只用来提示分歧，不影响分数
```

### 两条铁律

**一、模型判，代码算。**

模型只输出「命中 / 未命中」和原文证据，**所有算术都在 Python 里**。不让模型算分，因为它算不准，而且同一份答卷两次可能算出不同结果。

**二、二元判定，没有「部分命中」。**

每个要点只有两种结果：命中（拿满这点的分）或未命中（0 分）。

这条约束有个连带后果 —— **采点必须拆得足够细**：

```
❌ 一条要点：「开展专项联合执法行动，铲除犯罪组织」
   → 考生只写「开展联合执法行动」也会被判命中整条

✅ 拆成两条：「开展专项联合执法行动」/「铲除犯罪组织」
   → 各判各的，答一半就只拿一半的分
```

### 得分公式

```
得分 = 命中要点数 / 要点总数 × 满分 − 形式扣分
```

**要点等权**，考点（分组标签）只是显示用，不影响分数。满分由你自己填 —— 同一题型满分并不固定。

## 项目结构

```
├── launcher.py              打包后的启动入口
├── build_portable.py        组装 Windows 便携版
│
├── server/                  服务层（薄壳，不含批改逻辑）
│   ├── main.py              6 个 HTTP 路由
│   ├── models.py            请求/响应模型
│   ├── config.py            配置与 API Key 存放
│   └── static/index.html    单页前端（无构建链）
│
├── pipeline.py              批改主流程
├── routing.py               题型判别 + 规则库加载
├── scoring.py               计分（纯代码）
├── rules_check.py           形式检查（纯代码）
├── validators.py            输出校验与兜底修复
├── llm.py                   模型调用封装
├── pdf_import.py            PDF 文字提取
│
├── prompts_summary.py       概括归纳 / 提出对策 规则库 + 提示词构建
├── prompts_comprehensive.py 综合分析 规则库
├── prompts_zhixing_*.py     贯彻执行 规则库（通用格式 + 4 个子类）
│
├── tools/
│   ├── measure.py           基准集测量
│   └── run_once.py          手动跑一次的调试脚本（会真调模型）
│
├── server/tests/            服务层测试（23 个，不调模型）
└── tests/                   计分逻辑单元测试
```

**服务层是薄壳** —— 只做校验、转换、承载。批改逻辑一行都不在那里。这样下面那层能独立测试。

**测试分两类**：`tests/` 和 `server/tests/` 是自动化测试，不花钱、不联网；
`tools/run_once.py` 是手动调试用的，会真的调模型。

## 技术栈

```
Python 3.13
openai          → DeepSeek API
FastAPI         → 本地 HTTP 服务
uvicorn         → ASGI 服务器
pypdfium2       → PDF 提取（可选）
```

**刻意没用的东西**：LangChain / LangGraph（流程是一条直线，没有分支和循环）、向量数据库（规则全量注入比检索更可靠）、前端框架（界面只有几个输入框，上构建链会让打包复杂一倍）、数据库（不存批改历史）。

## 常见问题

**黑窗口一闪就没了**
启动出错。再双击一次，窗口会停在错误信息上。

**Windows 弹防火墙提示**
点「允许」。程序只监听 `127.0.0.1`，不对局域网开放。

**PDF 导入报「抽不出文字」**
大概率是扫描版 PDF（整页是图片）。需要先做 OCR，或者手动把文字打进去。

**同一道题两次批改分数不一样**
采点和判点都设了 `temperature=0`，但**模型 API 不保证 100% 确定** —— 浮点运算顺序、服务端批处理、路由策略都可能引入微小差异。

实测踩过一次严重的：同一份答卷两次跑出 **20 分和 14.7 分**。根因是判点当时写的是 `temperature=0.1` —— 19 个要点逐个做二元判断，每一次采样都可能翻转，累积起来就飘了。**已改成 0。**

> 前提是**关掉思考模式**：思考模式下 `temperature` 会被忽略，想控温就得先关掉它。

如果还遇到明显波动，**先看「逐点命中」而不是总分** —— 判断「这个要点答到没有」比判断「总分该多少」客观得多。

**分数偏低 / 偏高**
已知的偏差方向：**采点粒度比参考答案更细，分母更大，分数可能系统性偏低。**

所以建议当逐点检查表用，别把分数当权威 —— 这块要靠基准集才能量化。

## 你的数据会去哪

```
你输入的题目 / 材料 / 参考答案 / 答卷
        │
        ├─→ 只存在你自己的电脑上（浏览器内存里，不落盘）
        │
        └─→ 批改时发往 DeepSeek 接口，本项目不额外留存
```
